Vector in java is part of the java.util packages amd is one of the legacy classes (A legacy class in Java is an 
original class from early Java versions (JDK 1.0) that was designed to store objects before the Java Collections 
Framework was introduced in Java 1.2.) in Java that implementations the List interface.


Vector is synchronized means that it is thread-safe—only one thread can access and modify the Vector at a time.

When a thread calls a synchronized method on a Vector:
1. Acquires a Lock: The thread acquires an intrinsic lock (monitor) on that specific Vector object.
2. Blocks Other Threads: If a second thread tries to call any synchronized method on that same Vector, it is 
forced to pause and wait until the first thread finishes.
3. Releases the Lock: Once the first thread exits the method, it releases the lock, allowing the next waiting 
thread to proceed.



Why This Matters (Pros & Cons)

• Prevents Data Corruption (Pro): If multiple threads add or remove items simultaneously without synchronization, 
  they can overwrite each other's changes or throw a ConcurrentModificationException. Vector prevents this 
  automatically.
• Performance Overhead (Con): Acquiring and releasing locks takes extra processing time. In a single-threaded 
  application (where no other threads are competing for the data), you pay a performance penalty for thread 
  safety you don't even need.
• Compound Operations Are Still Not Safe (Caveat): While individual methods are synchronized, combining two 
  operations is not. For example, checking if (!vector.isEmpty()) and then calling vector.get(0) is not 
  atomic—another thread could delete the last element right between those two lines.
